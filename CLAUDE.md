# CLAUDE.md

## Project Overview

vShelf is a single-page web app: three virtual shelves — a vinyl shelf for an Apple Music collection, a movie shelf for streaming titles, and a book shelf — switched via a header tab. Same architecture family as the `Repertoire` project — single HTML file, JSON data, localStorage + GitHub push/pull, multiple profiles.

## Architecture

- **Single-file app**: all HTML/CSS/JS lives in `index.html`. No build step, no frameworks.
- **Storage**: `localStorage`, seeded from a per-profile JSON file on first load. Each of the three shelves (Music, Movies, Books) has its own storage key and seed file.
- **Profiles**: `?profile=<name>` in the URL (default `main`) namespaces the `localStorage` keys and the seed filenames — `vshelf_<name>.json` (Music), `vshelf_movies_<name>.json` (Movies), `vshelf_books_<name>.json` (Books). The profile *registry* (which profiles exist) lives unnamespaced in `localStorage['vshelf_profiles']`, so every profile's page load can see it; falls back to `DEFAULT_PROFILES` if empty.
- **Hosting**: static files via GitHub Pages.

## Files

| File | Description |
|------|--------------|
| `index.html` | Entire app |
| `vshelf_main.json` | Seed data for the default (`main`) profile's Music shelf |
| `vshelf_movies_main.json` | Seed data for the default (`main`) profile's Movies shelf |
| `vshelf_books_main.json` | Seed data for the default (`main`) profile's Books shelf |

## Data format

Music (`records`):
```json
{
  "records": [
    { "id": "…", "title": "…", "artist": "…", "appleMusicUrl": "…", "artworkUrl": "…", "type": "album", "owned": "no", "year": 2015, "tags": "…", "rating": 3.5, "addedAt": "YYYY-MM-DD" }
  ]
}
```
`type` is `'album'`, `'single'`, or `'compilation'` (default `'album'`) — not shown on the cover, just carried through from where the record was added and used for filtering/sorting. `owned` is `'no'` (default), `'vinyl'`, `'cd'`, or `'other'` — whether a physical copy is owned, likewise not shown on the cover, just used for filtering/sorting. `year` is the release year (number, or absent). `tags` is a free-form comma list. `rating` is `0`–`5` in `0.5` steps (`0`/absent = unrated).

Movies (`movies`):
```json
{
  "movies": [
    { "id": "…", "title": "…", "director": "…", "actors": "…", "streamingUrl": "…", "imdbUrl": "…", "posterUrl": "…", "format": "movie", "service": "netflix", "owned": "no", "watched": "no", "rewatched": false, "year": 2015, "tags": "…", "rating": 3.5, "imdbRating": 8.1, "lastViewedAt": "YYYY-MM-DD", "addedAt": "YYYY-MM-DD" }
  ]
}
```
`streamingUrl` is where it's actually watched (Netflix/Prime/etc.) — that's what opens on cover click, analogous to `appleMusicUrl`. `imdbUrl` is only ever used to fetch metadata (see below), never opened directly. `director` and `actors` are free text, both fetched from OMDb when available (`Director`/`Actors`) and editable by hand afterward; `director` is the Movies analog of Music's `artist` — shown on the cover caption (with `year`) the same way `artist` is, and filterable/sortable the same way. `format` is `'movie'` or `'series'` (default `'movie'`), inferred from OMDb's `Type` field — the Movies analog of Music's `type`. `service` is one of `netflix`/`prime`/`disney`/`max`/`hulu`/`appletv`/`paramount`/`other`. `owned` is `'no'` (default), `'dvd'`, `'bluray'`, or `'other'` — the Movies analog of Music's `owned` (physical-media ownership, independent of streaming availability). `watched` is `'no'` (default) or `'yes'`. `rewatched` is a plain boolean (default `false`), set via a checkbox in the edit form — whether it's been watched more than once. `lastViewedAt` is a manually-set date string (`YYYY-MM-DD` or `''`), independent of `addedAt`. `rating` is the same personal `0`–`5` half-step field as Music; `imdbRating` is a separate, read-only `0`–`10` number carried straight from OMDb, never user-edited.

Books (`books`):
```json
{
  "books": [
    { "id": "…", "title": "…", "author": "…", "sourceUrl": "…", "coverUrl": "…", "format": "novel", "owned": "no", "language": ["english"], "reread": false, "year": 2015, "tags": "…", "rating": 3.5, "lastReadAt": "YYYY-MM-DD", "addedAt": "YYYY-MM-DD" }
  ]
}
```
Books have no "open" link at all — no reading-app deep link the way `appleMusicUrl`/`streamingUrl` work for Music/Movies, since there's nowhere universal to send a click. `sourceUrl` is the Books analog of `imdbUrl`: an Open Library link, filled in by the metadata fetch (see below) and used only for reference/re-lookup, never opened. `author` is the Books analog of `artist`/`director` — shown on the cover caption with `year`, filterable/sortable the same way. `format` is `'novel'`, `'nonfiction'`, or `'shortstories'` (default `'novel'`). `owned` is `'no'` (default), `'physical'`, or `'digital'`. `language` is an array subset of `['english', 'italian']` (zero, one, or both — set via two checkboxes in the edit form, not a single-select); Open Library's data doesn't reliably carry a language code, so unlike Movies' `format`/Music's `type` this field is never auto-filled, only ever set by hand. `reread` is a plain boolean (default `false`) — the Books analog of Movies' `rewatched`. `lastReadAt` is a manually-set date string (`YYYY-MM-DD` or `''`) — the Books analog of `lastViewedAt`.

## Key implementation details

- **Shelf switching**: a header tab (`.shelf-tab`, `switchShelf('music'|'movies'|'books')`) toggles which of `#music-panel`/`#movie-panel`/`#book-panel` is visible and sets `currentShelf`; the choice persists in `localStorage['vshelf_active_shelf']` (global, like edit mode). The three shelves have genuinely different record schemas, so filtering/sorting/rendering/the add-edit modal are separate, parallel implementations per shelf (`filteredSortedRecords`/`filteredSortedMovies`/`filteredSortedBooks`, `renderShelf`/`renderMovieShelf`/`renderBookShelf`, `openEditModal`/`openEditMovieModal`/`openEditBookModal`, etc. — Movies' names are the Music ones with "Movie"/`m` swapped in, Books' with "Book"/`bk`). What *is* shared is the schema-agnostic plumbing — GitHub push/pull, export/import, force-refresh — written once and driven by `shelfCtx()`, which returns `MUSIC_CTX`, `MOVIE_CTX`, or `BOOK_CTX` (each a `{storageKey, seedFile, ghCfgKey, arrayKey, getDb, setDb, render}` bundle) depending on `currentShelf`. Push/Pull/Refresh/Export/Import/GitHub-settings in the header and ⋯ menu are the same buttons regardless of which shelf is open — they just act on whatever `shelfCtx()` currently points at. The repo-sync-diff banner (`checkRepoSync`/`#sync-banner`) is Music-only for now; Movies and Books don't check for repo drift on load.
- **Apple Music**: metadata comes from the public, CORS-enabled iTunes Lookup API (`itunes.apple.com/lookup?id=`) — no auth needed. `parseAppleMusicUrl()` pulls the numeric id out of a `music.apple.com` URL (either the path's trailing id, or `?i=` for a track); `fetchAppleMusicMeta()`/`fetchFromLink()` look it up and fill the form, including `year` from `releaseDate`. `type` is inferred from the lookup response since iTunes has no direct "single" field: a track-level link (`?i=`) is treated as a single, a collection with `collectionType === 'Compilation'` as a compilation, else album — always editable by hand afterward. Artwork is upsized by rewriting the `NNxNNbb` segment of `artworkUrl100`. There used to be an in-app "Search Apple Music" tab (`itunes.apple.com/search`) for adding without a link, but its relevance ranking was unreliable enough for well-known albums (some real titles never surfaced at all against a flood of unrelated same-titled singles) that it was dropped — paste-link is the only add path now. Discogs was tried as a secondary cover-art source and later dropped too.
- **IMDb / Movies**: IMDb itself has no public API, so metadata (title, year, poster, director, actors, genre, format, `imdbRating`) comes from OMDb (`omdbapi.com`), a free key-gated JSON API that wraps IMDb's data — the key lives in `localStorage['vshelf_omdb_key']` (global, entered via ⋯ → "OMDb API key…"). Unlike Apple Music, a pasted Netflix/streaming link carries no IMDb id to resolve, so the Movies add/edit modal has two separate link fields: **IMDb Link** (`parseImdbUrl()` pulls the `tt…` id out of an `imdb.com/title/...` URL; `fetchImdbMeta()`/`fetchFromImdbLink()` look it up via OMDb and fill title/year/poster/tags/director/actors/format/`imdbRating` — used only for the lookup, never stored as the "open" link) and **Streaming Link** (`streamingUrl`, pasted directly, required, no fetch behavior — it's just where the movie actually opens from on cover click). `director`/`actors`/`format` all stay editable by hand afterward, same as everything else OMDb fills in.
- **Open Library / Books**: Goodreads has no usable public API for new integrations (Amazon closed it to new developers in 2020), so metadata (title, author, cover, year, categories) comes from Open Library (`openlibrary.org`, run by the Internet Archive) — free, CORS-enabled, and needs no key at all, unlike OMDb. `parseOpenLibraryInput()` accepts a bare ISBN-10/13 (digits, optional `978`/`979` prefix, optional trailing `X`), an `openlibrary.org/works/OL…W` link, or an `openlibrary.org/books/OL…M` (edition) link. An ISBN or an edition link resolves in one call via `fetchOpenLibraryMeta()`'s use of the `api/books?bibkeys=…&jscmd=data` endpoint, which returns authors already resolved to names; a work link — what most people actually copy off an Open Library title page — takes a second fetch to resolve the author's name from their separate `/authors/OL…A` record, since the work record only holds an author *key*. `fetchFromBookLink()` fills title/author/year/cover/tags (from `subjects`, capped to 5 and normalized since editions return `[{name,url}]` while works return plain strings). Open Library's data doesn't reliably carry a language code, so unlike Movies' OMDb-derived `format`, `language` is never auto-filled — `fetchOpenLibraryMeta()` always returns `language: []`, left for the checkboxes to be set by hand. Books have no equivalent of Apple Music's link or IMDb's link-that-opens-nothing-either — there is no "open" action for a book at all, so the lookup field (`sourceUrl`) is purely for reference, same non-opened role `imdbUrl` plays for Movies.
- **GitHub push/pull**: same pattern as Repertoire — GitHub Contents API (GET for sha, PUT to commit) via the shared `githubGetFile()`/`githubPutFile()` helpers; config in `localStorage[ctx.ghCfgKey]`, one token/repo/branch/path per profile *and* per shelf (Music, Movies, and Books each push to independent files/targets by default). **🔄 Refresh** (`forceRefresh`) is the header's always-visible, no-token hard-refresh — refetches the active shelf's seed file and hard-reloads `index.html` itself (cache-busted), same `hardReloadPage()` mechanism as Repertoire.
- **Edit mode**: a header checkbox (`localStorage['vshelf_edit_mode']`, global — not per-profile) toggles a `body.edit-mode` class. There are no per-cover icons — `handleCoverClick()`/`handleMovieCoverClick()` check `body.edit-mode` at click time: with it on, clicking a cover opens the edit modal (whose footer has the only "🗑 Remove" button); with it off, clicking opens the record's Apple Music/streaming link instead. Books have no link to gate on, so `handleBookCoverClick()` ignores edit mode entirely and always opens the edit modal — it's the only path into a book at all, add or edit or remove. **＋ Add Record/Movie/Book** is unaffected and always available on every shelf.
- **Shelf visual**: the wood-ledge look under each row of covers is a single `repeating-linear-gradient` on the grid container's background, sized to the cover+gap row height — not per-row DOM. The vinyl disc "peeking" behind each cover is a `::` sibling div (`.vinyl-peek`), not a pseudo-element on the cover itself, so it can sit at a lower z-index without clipping. Movies and Books don't get a `.vinyl-peek` sibling — it's a Music-only flourish.
- **Rating**: no star glyphs anywhere in the UI — dropped after repeated, unfixable-in-that-form iOS/iPadOS home-screen Safari (WKWebView) rendering bugs (a `★★★★★` fill clipped via a CSS-custom-property width, then the same fill with an inline width, both still rendered every rating as a full 5 stars there). `rating` is still a `0`–`5` half-step number under the hood on all three shelves — settable via each edit form's rating range input (carries half-star units `0`–`10`; `rating = value / 2`, shown as plain text like "3.5 / 5") and usable for filtering/sorting; grouped shelves (below) are how it's surfaced on the shelf itself now instead of a per-cover badge.
- **Filter/sort**: toolbar dropdowns filter by format, owned, artist/director/author, year, tag, and rating (all populated from distinct values in the shelf, except format and owned which are fixed enums) on all three shelves, plus per-shelf extras: Movies adds service, watched, and rewatched filters; Books adds a reread filter and a language filter (checks whether the fixed value is present in that book's `language` array, since it's multi-valued rather than single-select). Each shelf's owned dropdown's blank option is "Any" (no filter); its "All owned" option filters to any non-`'no'` value, separate from the exact per-shelf enum options. The search box covers title/artist/tag text on Music, adds director/actors on Movies, adds author on Books. Sort adds format, owned, year, and tags to the usual title/artist-or-director-or-author/rating/date-added options, plus service/watched/rewatched/director on Movies and language/reread/author on Books. Every sort mode groups the shelf into separate `.shelf-group` sections by whatever field it primarily sorts on — a labeled header per distinct value (e.g. one shelf per rating, per year, per format, per artist) — except the chronological sorts, which stay one flat shelf since they have no natural bucket: both "added" sorts on every shelf, plus "last viewed" on Movies and "last read" on Books. `groupRecords()`/`groupMovies()`/`groupBooks()` in each shelf's render function just chunk the already-sorted list by consecutive equal key (via each shelf's own `groupKey()`/`groupLabel()` pair, keyed off that shelf's sort-mode variable), they don't re-sort or re-bucket independently — the grouping is only correct because it relies on the primary sort key being contiguous, which each shelf's comparators (primary key first, secondary tie-breaker after) guarantee.
